\section{1. Descripción técnica-conceptual del proyecto a realizar}
\label{sec:descripcion}

% El bloque "consigna" se usa para poner texto en rojo y dar una pequeña ayuda sobre cómo completar la sección. En cada entrega parcial deben eliminar los comandos begin y end del bloque consigna de las secciones que hayan completado.
Empresas Melo S.A. es una empresa de Panamá con una integración vertical en la industria avícola. La compañía se encarga de todo el proceso productivo, desde la creación de alimentos para pollos a partir de materia prima, pasando por la crianza de pollos de engorde, gallinas ponedoras de huevo y pollos para reproducción, hasta llegar a una planta de sacrificio donde se procesan los pollos según la demanda. Finalmente, los productos pueden ser enviados a una planta de valor agregado donde se crean artículos como nuggets, milanesas, entre otros.

El proyecto se enfoca en la planta de valor agregado, específicamente en la línea de producción de nuggets de pollo. El proceso de producción de los nuggets se compone de las siguientes etapas:

\begin{enumerate}
	\item Moler pollo
	\item Darle forma de nugget
	\item Aplicar una primera mezcla
	\item Aplicar harina
	\item Aplicar una segunda mezcla
	\item Freír el nugget
	\item Congelar el nugget
	\item Empacar y etiquetar	
\end{enumerate}

Todo este proceso se realiza en una sola línea continua, donde cada paso es llevado a cabo por un equipo diferente. El transporte del producto entre los distintos equipos se efectúa mediante cintas transportadoras, y en las transiciones entre las cintas ocurren dos cambios importantes: de altura y de velocidad. Estos cambios de altura y velocidad, junto con errores dentro de los mismos equipos, engloban casi en su totalidad a las causas por las cuales algunos nuggets no se procesan correctamente. 

Actualmente, el porcentaje de producto que no se procesa adecuadamente es aproximadamente  4\%. Aunque este porcentaje no es alto, dado el gran volumen de producción, estas pérdidas pueden llegar a representar 27 toneladas de nuggets mensualmente. Sin embargo, el producto no se desperdicia: una parte se reprocesa y otra parte se vende a un costo menor. Ambos métodos tienen desventajas:

\begin{itemize}
	\item Reprocesamiento: La energía que se utilizó debe ser invertida nuevamente.
	\item Venta a menor costo: Resulta en una ganancia menor por unidad de energía y materia prima utilizada.
\end{itemize}

Como esta es una línea de producción activa, de operación continua y de gran relevancia, hacer ajustes y cambios no es sencillo, económico, y requiere coordinación. Para saber dónde enfocar los esfuerzos, se propone la instalación de cámaras especializadas en \textit{computer vision} (CV) en varios puntos de la línea de producción. Estas cámaras capturan imágenes de los nuggets y mediante un modelo de inteligencia artificial (IA) se clasifica los nuggets en distintas categorias:

\begin{itemize}
	\item Inconsistencia en la fritura.
	\item Nuggets montados uno encima del otro.
	\item Mal corte del pollo molido.
	\item Mal forma del nugget.
	\item Nugget correcto.
\end{itemize}

Estas imágenes se someten a un preprocesamiento para garantizar una entrada uniforme al modelo de clasificación. El modelo identifica la posición de los nuggets en la cinta transportadora y los clasifica en las categorías previamente definidas. A cada nugget se le realiza un seguimiento, y se establece un umbral que, una vez cruzado, asegura que el nugget sea contado solo una vez para evitar duplicados. Finalmente, se genera un reporte que detalla el conteo por zona (según la cámara) de cada clase de nugget. Tanto los resultados como el video en vivo de las cámaras son accesibles al personal de la planta, lo que permite una supervisión constante del proceso.

\section{3. Propósito del proyecto}
\label{sec:proposito}
El propósito de este proyecto es desarrollar un sistema de clasificación mediante cámaras de video instaladas en la línea de producción de nuggets, capaz de detectar, clasificar, dar seguimiento y conteo utilizando técnicas de IA y CV. Este sistema permitirá establecer en qué parte de la producción se está dando la mayor cantidad de errores, lo que permitirá al equipo de mantenimiento saber dónde concentrar sus esfuerzos para disminuir los errores. 

\section{4. Alcance del proyecto}
\label{sec:alcance}
El proyecto contempla la parte de hardware y software a desarrollar para el diagrama en bloques especificado en la figura \ref{fig:diagBloques}. A desarrollar por el estudiante están las siguientes tareas:

\begin{itemize}
\item Recibir las imágenes de las cámaras de video para iniciar el pipeline de preprocesamiento.
\item Implementación de un modelo que, por medio de técnicas de IA y CV, pueda clasificar por lo menos un 90\% de los nuggets que se encuentren presentes en una foto.
	\begin{itemize}
	\item Obtención de imágenes para el entrenamiento del modelo seleccionado.
	\item Etiquetado de las imágenes para permitir aprendizaje supervisado.
	\item Cada cámara debe darle seguimiento los nuggets y se debe definir un umbral que, una vez cruzado, haga el conteo. Así se evitan duplicados.
	\end{itemize}
\item Desarrollo de un reporte que indique, por zona (y por ende por cámara), la cantidad de cada categoría de nugget.
\item Creación de una interfaz que muestre a los usuarios finales la distribución de clases en vivo de la línea de producción.
	\begin{itemize}
		\item Al mostrar la distribución de clases, se mostrará qué porcentaje corresponde a nuggets correctamente producidos vs nugget con algún tipo de error, así como un desglose de los errores por su tipo.
	\end{itemize}	
\end{itemize}

A pesar de que está incluido en el alcance del proyecto, no será desarrollado por el estudiante la instalación de cámaras de video. Esto será tercerizado por \empclientename

\section{5. Supuestos del proyecto}
\label{sec:supuestos}
Para el desarrollo del presente proyecto se supone que:

\begin{itemize}
	\item Se dispone de 10 horas semanales para el desarrollo del proyecto.
	\item Se tendrá acceso a un stream continuo de video de todas las cámaras instaladas dentro de la línea de producción. 
	\item Se cuenta con una computadora con capacidad computacional suficiente, o un servicio tercerizado similar, para el entrenamiento del modelo de IA.
	\item Se tendrá disponibilidad limitada para ingresar a la planta y realizar trabajos dentro, dependiendo de la naturaleza de los trabajos a realizar.
	\item Se acepta un porcentaje de detección de 90\% para la identificación de nuggets en la línea de producción.
	\item Se acepta un porcentaje de error en la clasificación de 10\% por clase.
\end{itemize}

\section{7. Historias de usuarios (\textit{Product backlog})}
\label{sec:backlog}

Para el desarrollo del sistema de detección de errores en la línea de producción de nuggets, se presentan las siguientes historias de usuario. Cada historia se describe desde la perspectiva del usuario o cliente, indicando claramente el objetivo y la razón detrás de la solicitud.

Además, se ponderan utilizando la escala basada en complejidad, dificultad e incertidumbre, sumando los valores para aproximarlos al siguiente número de la serie de Fibonacci. Por ejemplo, si la complejidad del trabajo es media (5), la dificultad es alta (5) y la incertidumbre es baja (2), los \textit{story points} serían 13 (5 + 5 + 2 = 12, que se aproxima al siguiente número de Fibonacci, que es 13). Los criterios para calcular los \textit{story points} son los siguientes:

\begin{enumerate}

	\begin{itemize}
		\item Alta: 8
		\item Media: 5
		\item Baja: 2
	\end{itemize}
	\item \textbf{Dificultad del trabajo:}
	\begin{itemize}
		\item Alta: 5
		\item Media: 3
		\item Baja: 2
	\end{itemize}
	\item \textbf{Incertidumbre del trabajo:}
	\begin{itemize}
		\item Alta: 8
		\item Media: 3
		\item Baja: 2

\section{13. Gestión de riesgos}
\label{sec:riesgos}

A continuación se listan los potenciales riesgos que se podrían presentar en el desarrollo del proyecto. Para la estimación de la severidad (S) y la probabilidad de ocurrencia (O) de los riesgos se utiliza una escala del 1 al 10, donde 1 es el valor mínimo y 10 es el valor máximo.

a) Identificación de los riesgos y estimación de sus consecuencias:
 
Riesgo 1: poder computacional reducido para entrenamiento de modelos.
\begin{itemize}
	\item Severidad (S): 5. \\
	Riesgo de severidad media. La repercusión de no contar con gran poder computacional afecta los tiempos de entrenamiento mas no el desempeño de los modelos.
	\item Probabilidad de ocurrencia (O): 2. \\
	Se hará una investigación previa sobre los requisitos computacionales y el equipo a comprar/servicio a contratar, por lo que la posibilidad de este riesgo es baja.
\end{itemize}   

Riesgo 2: retrasos en la entrega e instalación de equipos.
\begin{itemize}
	\item Severidad (S): 3. \\
	Riesgo de severidad baja. Se pueden ir adelantando otras tareas mientras los equipos se compran y son instalados.
	\item Probabilidad de ocurrencia (O): 7. \\
	Los proveedores pueden experimentar problemas logísticos, especialmente en contextos internacionales, por lo que se asigna una probabilidad alta.
\end{itemize}

Riesgo 3: deterioro de cámaras dentro de la planta.
\begin{itemize}
	\item Severidad (S):  8.\\
	Las cámaras son fundamentales para el desarrollo el proyecto ya que ellas son las que obtienen los datos de entrada del modelo de IA.
	\item Probabilidad de ocurrencia (O): 2.\\
	El ambiente dentro de la planta es húmedo y refrigerado, pero ya existen cámaras instaladas. Si se siguen las mismas especificaciones técnicas que las cámaras existentes, no debe haber problemas de deterioro.
\end{itemize}

Riesgo 4: precisión baja del sistema para contar nuggets.
\begin{itemize}
	\item Severidad (S):  9.\\
	Un mal seguimiento del nugget a través de la cinta transportadora puede llevar a perderlo de vista y fallar a la hora de contar el momento en el que cruza el umbral. Un mal conteo de los nuggets puede concluir que los problemas de la línea de producción están en un punto que no es el correcto, y llevar a una mala decisión.
	\item Probabilidad de ocurrencia (O): 2.\\
	Las técnicas actuales de seguimiento por CV son avanzadas, incluso para seguimiento de múltiples objetos. Las mayores dificultades que tienen son para objetos de diferentes tamaños que se mueven en distintas direcciones. Como este no es el caso de este proyecto, ya que los nuggets son del mismo tamaño y se mueven en la misma dirección, la probabilidad de riesgo es baja.
\end{itemize}

Riesgo 5: precisión baja para detectar las distintas clases de nugget.
\begin{itemize}
	\item Severidad (S):  9.\\
	El objetivo principal del sistema es determinar el lugar con más fallos en la línea de producción para invertir en mejoras. Una baja precisión puede llevar a tomar una decisión mal informada y una subsecuente mala inversión.
	\item Probabilidad de ocurrencia (O): 4.\\
	Las distintas clases de nuggets son, visualmente, considerablemente diferentes. Se espera que la matriz de confusión pueda tener algunos fallos entre nuggets correctos y nuggets con algún problema, mas no muchos fallos confundiendo un nugget con un determinado problema con otro nugget con un problema diferente.
\end{itemize}

\section{14. Gestión de la calidad}
\label{sec:calidad}

\begin{itemize} 
\item Req \#1: precisión del sistema de detección de peso.
	\begin{itemize}
	\item Verificación: comprobar las predicciones de peso arrojadas por el sistema contra los datos estadísticos de antiguas parvadas que mantiene el personal de las fincas.
	\item Validación: mostrarle al cliente pesando pollos manualmente y comparándolo contra las predicciones del sistema.
	\end{itemize}
\end{itemize}

\begin{itemize} 
\item Req \#2: efectividad en detección de instancias de pollos.
	\begin{itemize}
	\item Verificación: verificar manual y visualmente que se identifique el porcentaje de pollos acordado en las imágenes capturadas por las cámaras.
	\item Validación: mostrarle al cliente los resultados del sistema y asegurar su satisfacción.
	\end{itemize}
\end{itemize}

\begin{itemize} 
\item Req \#3: durabilidad de las cámaras.
	\begin{itemize}
	\item Verificación: inspecciones visuales de las cámaras durante el desarrollo del proyecto.
	\item Validación: confirmar con el cliente que las cámaras funcionan correctamente después de un periodo de prueba en la finca.
	\end{itemize}
\end{itemize}

\begin{itemize} 
\item Req \#4: facilidad de uso de la interfaz.
	\begin{itemize}
	\item Verificación: realizar pruebas de usabilidad con usuarios representativos y recopilar feedback.
	\item Validación: obtener aprobación del cliente mediante sesiones de capacitación y uso de la interfaz.
	\end{itemize}
\end{itemize}

\begin{itemize} 
\item Req \#5: resiliencia a fallos de conectividad.
	\begin{itemize}
	\item Verificación: simular fallos de conectividad y evaluar cómo responde el sistema.
	\item Validación: asegurarse de que el cliente está satisfecho con el desempeño del sistema durante periodos de conectividad intermitente en la finca.
	\end{itemize}
\end{itemize}

\begin{itemize} 
\item Req \#6: mantenimiento y soporte técnico.
	\begin{itemize}
	\item Verificación: revisar los planes de mantenimiento y las capacidades de soporte técnico
	\item Validación: elaborar un check list del mantenimiento a realizar y obtener la aprobación del cliente.
	\end{itemize}
\end{itemize}

\begin{itemize} 
\item Req \#7: escalabilidad del sistema.
	\begin{itemize}
	\item Verificación: realizar pruebas que demuestren que el sistema puede manejar un aumento en la carga sin degradar el desempeño.
	\item Validación: confirmar con el cliente que el sistema puede expandirse, ya sea a otras fincas o colocando más cámaras, conforme a sus necesidades futuras.
	\end{itemize}
\end{itemize}

\begin{itemize} 
\item Req \#8: tiempo de respuesta del sistema.
	\begin{itemize}
	\item Verificación: medir el tiempo de procesamiento de las imágenes y la generación de resultados. 
	\item Validación: realizar pruebas en condiciones reales de uso y confirmar con el cliente que el sistema cumple con los tiempos de respuesta esperados.
	\end{itemize}
\end{itemize}

\begin{itemize} 
\item Req \#9: funcionamiento continuo del sistema.
	\begin{itemize}
	\item Verificación: simular fallos de fluido eléctrico y comprobar que el sistema no requiere manipulación para restablecerse.
	\item Validación: asegurarse de que el cliente está satisfecho con el desempeño del sistema durante fallas en el fluido eléctrico  en la finca.
	\end{itemize}
\end{itemize}

\begin{itemize} 
\item Req \#10: documentación.
	\begin{itemize}
	\item Verificación: crear manuales de usuario detallados y asegurar que sea comprensible.
	\item Validación: presentar la documentación al cliente y asegurar su satisfacción con a la misma.
	\end{itemize}
\end{itemize}
